四条硬性分层规则（代码中可验证）：

  1. 逻辑单位不继承 AActor：UBattleUnit 派生自 UObject，因此整套战斗可在无关卡、无渲染的条件下"无头"运行（Options.bHeadless 的设计意图）。Run 层的 FACRunMap / FACRunSquad / FACRunEconomy 同样是纯 C++ 结构体、不依赖 UWorld，因此"无头跑 N 局"只需换一个驱动方。
  2. AutoChessCore 不含逻辑：只放跨层共享的 POD / 枚举 / DataAsset 定义 / 纯函数几何工具，保证 Run 层布阵与战斗内核共用同一套坐标数学。
  3. 战斗内核只暴露"输入快照 → 输出结果"：FACBattleSetup 进、FACBattleResult 出，中间状态不跨越模块边界；Run 层没有任何其它方式影响战斗。
  4. Run 层只编排、不判定：不写数值、不判胜负、不选目标；战斗内核不知道地图 / 魂晶 / 招募 / 等级 / 装备栏的存在（ACRunSubsystem.h 头注释即写明这条边界）。

0.3 一次战斗的运行时序（UBattleWorld::Step）#

固定步长默认 1/30s，1 步 = 1 Tick。Step() 内部顺序（ACBattleWorld.cpp）：

1. ConsumeCommands()          消费命令队列（秘术卡 / 放弃战斗 / Debug）
2. Clock.Advance()            Tick++
3. SecondTick.Pump()          整数秒边界 → ExecuteSecondTick() 每秒管线
4. TimelineSystem.Update()    抢攻到期 / 后发触发
5. Scheduler.Advance()        行动条推进 → ReadyQueue（按 UnitId 升序）
6. foreach ReadyQueue: AbilityExecutor.RequestAction()  意图 → 技能 / 普攻 / 移动
7. AbilityExecutor.TickChannels() + TickStep()          引导结算 / 专注与眩晕按步结算

  1. 合并时要显式取 const 指针：
// 注意：本函数是 const，成员 EffectLibrary 是 const TObjectPtr。TObjectPtr 的 operator-> 返回

关键实现细节

  • bDispatching 递归安全：Dispatch 保存 bWasDispatching，只有最外层返回时才 ApplyPendingRemovals/ApplyPendingAdds；ApplyPendingAdds 会先把 PendingAdds 移出再逐个 FindOrAdd 插入（避免 InsertSorted 扩容期间持有元素引用）。

Recompute 算法（核心）

if (!bDirty) return;                          // 脏标记短路
固定顺序：Base → Permanent → BattlePermanent → BattleTemp
for each Stat:
    Value = Base[Stat]
    for each Scope in [Permanent, BattlePermanent, BattleTemp]:
        FlatSum = Σ(Add.Value * max(1,Stacks))            // 同层加法
        PctSum  = Σ(MulPct.Value/100 * max(1,Stacks))
        Value = (Value + FlatSum) * (1 + PctSum)          // 层间乘法（A2 默认）
    最后再扫一遍，取最后一个 Override 覆盖 Value      // Override 最后生效
    Current[Stat] = max(0, Value)                     // 不允许负属性
ApplyConversionRules(Sheet, -1)                       // 无时钟 → 振荡取中值，保证可复现
++Version; bDirty = false;
  • 浮点漂移防护：每次重算都从 Base 重新累加，而不是在上次结果上累加。
  • GetCritMultiplier：1.2 + max(0, 暴击值 - 100)/100 + 额外暴击伤害%。
  • GetCritChance：暴击值 clamp 到 [0,100] 后 /100。
  • GetAttackSpeedHz：每点攻速 = 每秒 0.01 次。
  • ApplyConversionRules 振荡相位：Phase01 = fmod(Tick/30/Period, 1)；当 CurrentTick < 0（重算路径传 -1）时取 0.5 中值——牺牲相位精度换取"无时钟场景下仍可复现"。

ApplyDamage(Request) —— 完整承伤顺序

0) 前置钩子：
     Dispatch(Hook.Damage.BeforeDeal) → 取消则 return（bCancelled）
     Dispatch(Hook.Damage.BeforeTake) → 取消则 return
   钩子 Context 会带上 Damage.Type.* 标签 + Request.Tags
   取 Damage = max(0, Context.FloatValue)      // 允许订阅者改值
1) 精神伤害特判：DamageType == Mental → 转交 FMentalSystem::ApplyMentalDamage，
   记 AfterMitigation/AfterIncreaseReduction 后直接 return（不扣血、不触发后续）
2) 暴击：bCanCrit && Source 有效 → Rng.RollChance(Source, Crit, 暴击率)；
   命中则 Damage *= GetCritMultiplier(...)
3) 类型减免 ComputeMitigation：
     Physical : max(MinPhysicalDamage, Damage - max(0, DEF - 攻击方 DEFPen))
     Technical: Damage * (1 - clamp((RES - 攻击方 RESPen)/100, 0, TechResistCap))
     True/Mental: 不减免
4) 增伤/减伤 ApplyIncreaseReduction：flat + pct 两层叠加 → (Damage + Flat) * (1 + Pct)
5) 护盾吸收（bIgnoreShield 可跳过）→ 派发 Hook.Shield.Gain；池被打光则派发 Hook.Shield.Broken
6) 扣血：AppliedHpLoss = max(0, AfterIncreaseReduction - ShieldAbsorbed)
     Overkill = max(0, AppliedHpLoss - HpBefore)
     血量归 0 → MarkPendingDeath(Request.Source)（真实死亡在步骤末 ResolveDeaths 统一落地）
7) 后置吸血：Source != Target 时 ApplyLifesteal(按 DeclaredJudgment 口径)
8) 事件与统计：Dispatch(Hook.Damage.Take) + Dispatch(Hook.Damage.Dealt)
     RecordDamageStats(Source, Target, AppliedHpLoss, AppliedHpLoss)
  • 两段式前置钩子：BeforeDeal（攻击方视角，可加伤）/ BeforeTake（承伤方视角，可免疫）无短路隔离，都作用于同一 FloatValue。

  • 先快照 InstanceId 列表（不遍历数组本身），因为结算过程中钩子可能再次施加状态导致数组扩容；

  • 推进 NextTickAt = CurrentTick + SecondsToTicks(TickInterval) 后进入 ApplyTickEffects；
  • 最后 RemoveExpired()。

  1. ++TriggerCount；

  4. 重新定位后广播 Hook.State.Tick。

3.8 M02 子模块 · 确定性随机数 —— ACBattleRng.h#

模块定位：每场一个 seed；按 (UnitId, 通道, 抽取序号) 派生随机流，避免遍历顺序影响结果。

  • EACRngChannel：Crit / Status / Target / Loot / Effect / Misc（+ Count），共 6 条通道，ACRngChannelCount 常量导出。
  • FBattleRng 接口：
    • Initialize(Seed)：InSeed == 0 时兜底为 1；重置全部计数；预分配 256 个分桶；
    • Roll01(Source, Channel)：[0,1)；RollInt(Source, Channel, Min, Max)：闭区间（Max <= Min 时直接返回 Min）；RollChance(Source, Channel, Chance)：<=0 返回 false、>=1 返回 true；
    • GetSeed() / GetDrawCount()（总抽取次数，写日志/结果，M02 §9 要求）/ GetChannelDrawCount(Source, Channel)（供批测比对）。

核心机制：

  • 分桶键 Key = (UnitId << 8) | Channel，每桶独立维护 DrawIndex；
  • 每次抽取：FRandomStream Stream(MakeStreamSeed(Source, Channel, DrawIndex)) → 用完后 ++DrawIndex、++TotalDrawCount；
  • MakeStreamSeed = BaseSeed 依次 HashCombine(Source)、(Channel)、(DrawIndex)，最后 | 1u 保证非零；

为什么这样设计（注释原文）：抽取序号按 (UnitId, 通道) 单独计数，因此增加一个无关单位的抽取不会改变其他单位的结果——这是"同 seed 可复现 + 增量改内容不破坏历史金样"的关键。

  1. 置 Attacking；若目标仍有效则转向目标（按 Row 差决定 Up/Down）；
  2. 派发 Hook.Attack.Before 与 Hook.Ally.Attack（友方普攻事件，订阅者按 Source 阵营自行过滤）；
  3. 取 Pattern.Segments；为空时用函数内静态兜底段（100% 攻击力物理伤害，一次性惰性初始化）；
  4. 治疗型普攻 → 走 ApplyHeal（RawAmount = ATK * HealRatio，SourceEffectBlockId = "BasicAttackHeal"）；否则逐段逐次命中：
    • RawAmount = ATK * Segment.Multiplier，bCanCrit = Segment.bCanCrit && Pattern.bCanCrit；
    • ApplyDamage → 段级 OnHitEffectBlockIds 效果块 → 暴击则派发 Hook.Attack.Crit → 派发 Hook.Attack.Hit；
  5. IncrementAttackPatternHits()（命中计数，供表现/AI）→ 派发 Hook.Attack.After → OnBasicAttackHit(Unit)（射手回专注）→ 回到 Idle。

ExecuteSkill(Unit, Skill, Targets)

  1. 构造 FSkillCastContext 与钩子上下文；
  2. 敌方技能打断通道：Team == Enemy 时派发 Hook.Enemy.SkillCast，若返回 bInterrupt → 置 Idle + 派发 Hook.Skill.Interrupted + 直接 return（"J 监视"类效果块订阅此钩子）；
  3. 派发 Hook.Skill.Before，bCancel/bCancelled 则中止（不打断，直接放弃施放）；
  4. 置 Channeling（引导）或 Casting（瞬发）；
  5. 专注消耗按 CostMode 分支：ClearAll → GrantFocus(-Current)；Fixed → GrantFocus(-FixedCost)；DrainPerSecond → 打开 bDrainMode、关闭 bGainEnabled 并记 DrainPerSecond；None → 不消耗；
  6. 派发 Hook.Skill.Cast 与 Hook.Ally.SkillCast；
  7. 执行 Skill.EffectBlockIds；
  8. Channel 类型 → 建立 FActiveChannel（NextTickTick = Start + ChannelTickInterval、EndTick = Start + ChannelDuration）；Instant 类型 → 回到 Idle。

TickStep(CurrentTick)（按固定步每秒 30 次）

  • 眩晕到期：倒序遍历 Stuns，到期移除；同一单位可能有多条记录，只有全部到期才解除（SetStunned(false) 且把 Stunned 状态复位为 Idle）；
  • 专注按步结算：bDrainMode 时按 DrainPerSecond * FixedDt 扣减，扣到 0 则关闭 drain、恢复 gain、并 InterruptChannel(External)；否则 bGainEnabled && RegenPerSecond > 0 时按 RegenPerSecond * FixedDt 回复。

TickChannels(CurrentTick)：倒序遍历引导实例；bFinished 或超过 EndTick → 施法者 Idle 并移除实例；到达 NextTickTick → 推进时间并执行 ChannelTickEffectBlockIds。

InterruptChannel(Caster, Cause)：置 Idle、保留当前专注（A15，不再继续消耗）、清理 drain 标记、移除实例、派发 Hook.Skill.Interrupted（IntValue = Cause）。

ApplyStun(Target, Seconds, Source)：置 Stunned=true + ActionState=Stunned → InterruptChannel(Stun) → 已有条目则 EndTick = max(旧, 新)（A18：叠加眩晕取最晚到期，避免先到期的记录提前解除），否则新增条目。

专注读写

  • GrantFocus(UnitId, Amount)：Current = clamp(Current + Amount, 0, Max)；跨越满值时派发 Hook.Focus.Full；值发生变化则派发 Hook.Focus.Changed（FloatValue = 新 Current）。注意 DrainFocus 只是 GrantFocus(负数)，因此扣减也会走同一套钩子。
  • OnBasicAttackHit(Unit)：A11——优先取 Focus.PerAttackGain；为 0 且单位是远程时回退 RuleConfig->ShooterFocusPerAttack（默认 5）。
  • OnTakeHit(Unit)：持有 Unit.Class.Tank 时 +RuleConfig->TankFocusOnHit（默认 1）。

HandleHook(HookTag, Context) —— 钩子触发的核心

1) 若 CurrentTickStamp != 当前 Tick → 重置全局计数并清零所有实例的 TriggersThisTick（A20）
2) 收集候选 InstanceId（用栈上 TInlineAllocator<32> 缓冲）
   —— 刻意不用成员缓冲：本函数在执行效果时会被重入，共享缓冲会被内层调用清空
3) 逐实例：
   重新定位下标（可能已被注销）→ 校验 Block 存在/启用/TriggerTag 匹配
   → 到期检查 → CheckFrequencyGuard（频率守卫）→ CheckGlobalTickGuard（全局每 tick 上限）
   → 构造 EffectContext（带 ParentInstanceId / Tags / bWasCrit）
   → EvaluateConditions（条件不满足则跳过）
   → ExecuteBlock（递归执行；Depth 由 ExecuteBlock 自增/自减守护）
   → 执行后重新定位并递增 TriggerCount / TriggersThisTick、写 LastTriggerTick；
      若 TriggerPolicy == Once 则置 ExpireTick = Now（等效"用过即废"）

频率守卫 CheckFrequencyGuard：

  • Once && TriggerCount > 0 → 拒绝；
  • MaxTriggers > 0 && TriggerCount >= MaxTriggers → 拒绝；
  • A20 单实例每 tick 上限（RuleConfig->EffectMaxTriggersPerInstancePerTick，默认 8）；
  • 冷却：Cooldown 策略下 CooldownSeconds <= 0 时强制按 1 秒处理；其余策略仅在显式配置时生效；命中冷却时拒绝。

CheckGlobalTickGuard：TriggersThisTick >= EffectMaxTriggersPerTick（默认 256）时打 Warn 并中断本 tick 剩余处理（HandleHook 中 break、TickPeriodic 中 return）。

ExecuteBlock(BlockId, Context)

  1. 库/世界/ID 校验 + Block.bEnabled 校验；
  2. 递归深度守护：CurrentDepth >= EffectMaxDepth（默认 4）→ Warn 并返回；否则 ++CurrentDepth；
  3. 按值解析目标（用局部 TArray<FUnitId> 而非成员缓冲，因为本函数会递归）；
  4. 逐个 Action：解析动作级目标（尊重 bHasTargetSelectorOverride），为空则回退块级目标，再为空则兜底为 Context.Source（保证 Self 类动作仍可执行）；
  5. 对每个目标构造 ActionContext（覆盖 PrimaryTarget / Targets）→ ExecuteAction；
  6. --CurrentDepth。

ResolveActionTargets：选择器 = 动作覆盖值或块值 → World->Targeting().ResolveSelector(Selector, *Source, Block.SelectorRadius, OutTargets)；为空时回退 Context.PrimaryTarget。

4.6 FACRunPostBattle（战后流转）#

  • 文件：Public/Run/ACRunPostBattle.h + Private/Run/ACRunPostBattle.cpp（152 行）
  • 类型：全静态类（ApplyResult(...) 为静态函数）
  • 作用：把战斗内核的唯一出口 FACBattleResult 翻译成局内后果；不修改战斗世界（此时已 Shutdown），也不做任何数值计算。

ApplyResult 的四步（顺序即文档语义）

  1. 血量持久化：遍历 Result.Units，用 UnitsToOperators[Index]（参战顺序 → 干员 ID，与 PlayerUnits 同序）对齐 → RecordBattleResult。存活单位会把 RemainingBaseHP 收敛回 [1, GetDerivedMaxHP]（战斗中可能被治疗/护盾/临时上限抬超基础值域）。
  2. 阵亡标记（由 RecordBattleResult 写 bDead）→ 收集 Outcome.DeadOperatorIds。
  3. 奖励结算：SoulCrystalFromBattle = Result.SoulCrystalDelta（战斗内 GrantSoulCrystal 效果动作产出）；胜利时再加节点奖励 GetNodeVictoryReward(Config, NodeType)（遇敌 8 / 精英 14 / 挑战 18 / BOSS 40 / 篝火 5），可选叠加"每击杀"收益（SoulCrystalPerKill，默认 0，统计源为 Stats.KillsBySourceUnit）；掉落品级 GetNodeLootTier（遇敌白 / 精英蓝 / 挑战金 / BOSS 红 / 遗物 RelicEquipmentMaxTier），从内容池用 RewardStream 抽一件并给名字加节点前缀（如"首领遗物 · 心流刃"）；掉落池为空时打 Warning 指向 BuildEquipmentPools。
  4. 失败处理：Outcome.bSquadWiped = !Squad.HasAnyAlive()（消费者 UACRunSubsystem::FinishEncounter 据此 SettleRun(false)）。

输出结构 FACRunBattleOutcome：bVictory、NodeType、SoulCrystalGained（含拆分 FromBattle / FromNode）、Loot、DeadOperatorIds、bSquadWiped、BattleTicks、StateHash。

⚠️ 本轮修复的真实编译错误（R8，已解决）

原代码是这样的：

TArray<FString> LogLines;                                     // ← 局部变量遮蔽（shadow）了本类的成员 int32 LogLines
Run->BuildLogText(LogLines).ParseIntoArrayLines(LogLines, ...); // ← 把 TArray<FString> 传给 FString BuildLogText(int32 MaxLines = 8)

两处问题：① 实参类型不匹配（TArray<FString> 无法隐式转换为 int32）；② 局部变量 LogLines 遮蔽了同名成员 LogLines（MSVC C4458 告警）。修法是把局部数组改名，让 LogLines 重新解析为那个 int32 成员（于是它终于真的起作用了）：

// 注意：BuildLogText(MaxLines) 返回的是**拼好的多行字符串**（不是把行写进 TArray），
// 因此先取字符串、再按行切分。局部变量名不能叫 LogLines —— 那是本类的成员（C4458 遮蔽告警）。
TArray<FString> LogTextLines;
Run->BuildLogText(LogLines).ParseIntoArrayLines(LogTextLines, /*bCullEmpty=*/false);

教训：BuildStatusText() 与 BuildLogText() 的返回类型相同（都是拼好的多行 FString），但一个无参、一个带 MaxLines 参数，命名上不容易看出区别——调用方极易写成 BuildLogText(Lines)。若后续要改 API，建议把它们统一成 void BuildXxx(TArray<FString>& OutLines) 形式，从签名上消除误用可能。详见 §8.3 C13。
